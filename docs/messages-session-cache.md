# 消息会话与本地草稿边界

## 本次修复

消息 Store 的异步工作绑定开始时的用户 ID、认证 generation 和 Store epoch。账号 A → B → A、退出后重新登录同一账号、重置 Store 都会使旧工作失效。缓存读取之后、发起后续 API/缓存操作之前以及接收回执时都会检查归属；旧请求的 finally 只能释放自己持有的发送锁/去重记录。

同一群的本地写入、已确认草稿清理与精确删除按顺序执行。延迟写入保留归属和最新快照；保存返回 false 时不会当作成功清理待保存记录，也不会继续淘汰旧缓存。未完成写入之后的删除必须排在其后，避免较早的草稿写入复活已确认/已删除的记录。

发送和重试在发起网络请求之前尝试保存意图，沿用同一个 tempId/client_message_id。缓存等待结束后再次检查账号和意图是否仍存在；不会因为重新加载而自动重发。恢复的 `sending` 草稿显示为带“结果尚未确认”说明的可核对草稿；用户手动重试仍使用原标识。只有后端返回完全匹配的 client ID，或已确认的对应 WebSocket 消息，才能合并草稿。HTTP 连接随后失败不会把已确认消息重新标为失败。

最新页/较早页读取按请求开始后的消息修订合并，保留实时新增、编辑和未确认草稿。历史分页使用服务端页边界时间，不使用本地缓存中最早一行推断游标；即使边界消息被删除，也不会跳过未核对的历史区间。明确的消息删除、群清空及已核对页区间内的缺失记录按范围清理，普通刷新不会清空整个群的历史缓存。LRU 内存淘汰也不等于来源删除。

## WebSocket 接线约定

- `addMessage(groupId, message)` 对完全匹配的服务端 client ID 合并草稿，并自行排队清理对应的本地 tempId
- `confirmClientMessage(groupId, tempId)` 用于恢复过程已经拿到明确回执但不走 addMessage 的分支。它只清理该客户端意图，不生成“来源已删除”标记；不能用 removeMessages 替代回执清理
- `recoverCachedMessage(message)` 为缓存里的发送中草稿恢复结果待核对状态；WebSocket 的独立缓存加载路径也须使用它
- 首次历史页更新分页信息时，同时保存 oldestMessageId 与 oldestMessageCreatedAt
- WebSocket 仍需独立执行连接/账号 generation 检查。调用这些同步入口本身不能替一个旧连接判断账号归属

## 验证与剩余边界

`frontend/test/messagesAccountBoundary.test.mjs` 编译真实 Store 与 Zustand，用合成 API/存储 IO 和可控定时器验证精确的异步次序，不调用真实模型服务。覆盖跨账号、同账号新会话、旧发送锁、加载/编辑/反应/评论/删除错误回执、发送草稿恢复、精确回执、历史游标、实时编辑、来源删除和缓存失败顺序。

Store 检查不能替代 IndexedDB helper 在 open/transaction/删除中的归属检查，也不能替代 API 在调用当下冻结身份或 WebSocket 的旧连接隔离；这些实现应合并后一起验证。存储不可用、配额不足或删除失败时，草稿可能仅存于内存，关闭浏览器仍可能丢失；不会宣称已持久保存。此修复没有增加付费调用、自动重发、生产发布或真实浏览器验证。原生浏览器、多标签真实 IndexedDB 与最终整条身份链仍需要集成测试。


## 集成交界补充

`sessionCacheIntegration.test.mjs` 执行真实Axios、WebSocket服务、消息Store、cacheUtils和IndexedDB helper，仅底层存储事件/网络/DOM使用合成夹具。覆盖真实分页、同帧身份切换、发送前缓存等待、清理失败、清理前计时器与队列失效、旧版无owner缓存隔离及写入快照复制。

清理以独立缓存代次撤销已排队的写入，不重置业务请求或编辑中的内存。它不是永久禁用缓存：清理之后的新编辑和新回执可以再次保存。自动历史裁剪只针对已确认历史，不删除未确认发送副本。当前标签页之外的完整删除传播、存储不可用时的持久恢复，以及所有聊天子组件的交互重构仍不由本包保证。
