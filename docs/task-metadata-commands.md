# 任务标题、排期与规划属性的可靠编辑

现有任务更新继续遵循主计划第13.9节的幂等、修订及恢复边界。F14.1本次窄子集增加本人任务的显示优先级与可选预计分钟，和既有 `title`、`auto_run`、`run_at` 共用编辑链条。任务仍为当前账号私有对象；不增加多人负责人、实际工时统计、排序或调度策略、目标转换、外部办公自动化。

## 修订与兼容

任务返回 `metadata_revision`。旧数据没有该字段时只读投影为0；读取不写迁移、不更改原标题或排期。五个字段共用一个修订号。用户每个成功的新命令递增1，即使实际值未变化也保存回执并递增；同一原请求重放只读回原回执，不再次增加。

调度消费、重复运行更新下次时间、人工验收关闭主动执行、取消、失败或重启恢复等后台路径，实际改变标题或排期时也在同一次数据库写入内递增修订。旧页面不能用较早的修订覆盖后台已经调整的排期。仅修改前置依赖或文稿正文且未改变这五个字段不会增加此修订。

旧 `PATCH /api/tasks/:taskId` 的标题、主动执行、时间、优先级或预计分钟更新现在返回428 `TASK_METADATA_PRECONDITION_REQUIRED`，整次请求不写入。旧客户端需要刷新或升级；不能自动去掉前置条件重试，也不能因此丢掉用户输入。该PATCH只保留按精确 `run_id` / `cancel_request_id` 停止生成的既有语义，取消请求不能顺便编辑元数据。

## 命令接口

- `PUT /api/tasks/:taskId/metadata`：`client_request_id`（UUID）、`expected_revision`、非空 `changes`。
- `changes` 只允许 `title`、`auto_run`、`run_at`、`priority`、`estimated_minutes`。标题沿用1–150字符限制；时间为ISO UTC或null；非法或未知字段使整次请求失败。
- `GET /api/tasks/:taskId/metadata/commands/:requestId`：按原编号查询回执与当前任务。
- `POST /api/tasks/:taskId/metadata/commands/:requestId/close`：空对象，核对已提交命令或持久封存未提交原号。

回执包含 `id`、`operation: metadata`、`task_id`、`committed_revision`、`committed_at`、`status`。成功状态为`succeeded`；耐久封存为`cancelled`且提交修订为null。任务已经删除时返回 `task: null` / `task_deleted: true`，不会恢复任务。

请求编号和载荷摘要绑定账号、任务、修订及实际提交字段的原值意图。同编号改载荷或换任务拒绝；另一账号与不存在任务不区分。数据库同时保存字段、修订和回执，按现有账号写锁及底层CAS提交。每账号最多保留10000条元数据命令回执；达到上限后拒绝新增，不遗忘旧命令以释放重放入口。

运行中或结果未知的任务仍不允许修改设置。开启主动执行必须有执行时间；已完成或已取消任务不能直接开启主动执行。此编辑接口不派发模型，正常调度到点时仍走既有模型、预算、来源和前置依赖门禁。

## 冲突与未知结果

页面编辑时冻结所见修订，不因后台刷新偷偷改用新修订。冲突时保留输入，用户比较最新状态后才能明确重新编辑。发送后的409、查询404或网络中断均不能证明同号另一请求未提交。存储写入不确定时返回503；数据库读取中断也可能由通用错误处理返回500。所有5xx都须保留原号核验，不能把读失败当作原命令不存在。

未知请求保留原编号及原载荷；有可核验载荷时允许明确同号重试，否则只允许查询或封存。封存先持久保存墓碑，迟到原PUT返回410；原请求已经成功时只返回成功回执，不撤销已提交设置。只有核验到有效回执后才能放下该编号，不能生成新编号覆盖未知状态。

浏览器恢复按账号、任务、UUID分别记账，多标签的未决命令不会互相覆盖。标题、排期及规划属性值不明文写入恢复日志；仅在用户已开启既有草稿恢复时使用其账号隔离加密草稿。默认关闭恢复时，刷新或退出可能不再有可验证原载荷，仍保留查询/封存入口，不猜测或重建载荷进行重试。切换账号后迟到响应不能修改新账号状态。

## 存储与验收边界

本功能不创建新云资源或凭据，继续依赖现有可靠数据库和持久数据目录。任务及回执应一起恢复；任意将整个权威数据库回滚到命令发生前仍会遗失后来的回执，不能据旧快照证明外部请求从未执行。PostgreSQL多进程需保留现有CAS；LowDB仍只支持单进程写。

本次不是整个F14、F01–F52主计划或生产部署完成声明。准确测试结果应读取对应提交的验证回执；合成HTTP/DOM测试不等同原生浏览器或真实模型验收。

## 本轮确认的邻接恢复缺陷

同样的跨标签回执清理错误也在既有F14前置依赖编辑器中被独立真实React控件反例确认。本轮仅补意图归属：成功回执只能清除绑定该UUID且未被后来修改的本标签已发送草稿；核验另一标签的成功请求不会删除本标签尚未发送的前置选择。旧修订与本地选择继续保留，并要求明确比较当前关系后再编辑。此处不改变依赖权限、模型上下文或调度规则，也不将此前交付包中的历史测试结果改写成已覆盖该反例。

## F14.1 本人规划属性的窄定义

- `priority`：`null | low | medium | high`，显示“未设置／低／中／高”。没有默认中优先级；缺字段的旧任务仅读取投影为null。
- `estimated_minutes`：null或0–525600整数，显示“未估算”或“预计N分钟”；0表示明确零分钟。它是用户人工预估投入，不是运行耗时、模型用量、费用、SLA或多人负载。上限是输入保护，不是原主计划的工时制度。
- 只在创建/设置中保存，在同一任务卡显示已保存值。不改变任务数组、列表排序、到期先后、抢占、阻塞、状态或模型选择。规划属性编辑、读取和回执核验不额外派发模型；原本启用的定时生成仍遵从既有计划。
- 新建不填写可省略字段。新属性schema为optional，不能在请求哈希前加default。旧创建载荷、旧三字段metadata载荷、原v1 journal和AES格式不改；旧原号重放不能补字段、重排历史哈希或换号。同号显式追加null仍是不同载荷，必须冲突。
- 读取旧记录不补写字段、不改变updated_at/修订；明确存在但非法的持久值返回无法核实，不静默当未设置。API空字符串、数字字符串、负数、小数、布尔、未知值/字段整次拒绝。只有真正清空分钟控件才发送null；非法中间文本保留并禁保存。
- 标题/排期/规划属性使用整组CAS。后台改run_at也会令旧优先级草稿冲突，反之亦然；这是保守保护，不做字段自动合并。未知规划命令仍须核验后才能run/accept。改规划值不作废既有正文版本、来源或依赖验收证据。
- 旧客户端向新后端发三字段命令只改原字段，不重置规划值。新字段请求发往旧服务器被拒绝时，保留草稿和UUID；不能删字段降级重发。旧前端不认识新journal字段时保留存储并要求升级，不能让用户清除站点数据来释放未决号。
- 普通读取缺省与命令成功证据不同：新metadata命令同修订回执遗漏对应新字段时不能用null补齐确认。新创建回包也必须含有效规划属性；有原载荷且仍为初创修订时核对原显式值。历史回执返回较新Task时不拿旧值误判冲突。缺/非法回包保留原请求核验，不自动重试。

该子集不等于F14.1全部完成。真人多人责任分工、实际工时/负载、F14.2多视图与整个F14仍需独立实现和验收。原生浏览器、真实PG与旧公开代码产物消费的具体结果须绑定最终提交回执，不能从此文档推定通过。
