# 模型能力测试的付费效果与恢复边界

## API 与客户端责任

- `POST /api/user/model-catalog/test` 需要 `modelId` 和每次新意图的 UUID。优先用 `Idempotency-Key`，也接受 `clientRequestId`；二者同时出现必须一致，大小写规范化。`capability` 为 `chat`、`vision` 或 `tts`，缺省 `chat`
- 请求号必须在发送前生成。浏览器超时、关闭页面或网络失败都不表示供应商未调用。保存原请求号，使用 `GET /api/user/model-catalog/tests/:requestId` 查询；查询不会再次请求供应商
- 同一账号同一请求号重放原记录，换模型或能力返回冲突。换请求号提交相同模型、能力和配置的 `running/unknown` 意图也只返回原记录；新号作为别名持久记录，随后仍不会重新调用
- 客户端应总传开始操作时捕获的 `expectedRevision`。新准入若修订不匹配，返回 409 `PROBE_CONFIG_CHANGED`、`possibleCharge=false`，说明本提交没有发出新调用，未创建效果记录。同号重放须保留原版本条件；别名也绑定自身版本条件，不能改条件后用旧号发起新意图
- 仅在 GET 404、账号和配置版本未变时，客户端可以提供用户显式确认的“重新提交原测试请求（可能计费）”。须沿用原 UUID 与完整冻结输入，不自动执行；原 POST 延迟到达时仍只有一个准入者。这不是纯查询，若原请求从未到达会开始新的付费测试。对已有 `unknown` 不开放此入口；查询失败/503不能当作404
- 配置改变后的同号请求仍查询旧效果，不能替换为新调用。不同配置的新测试是新的显式意图，旧未知效果仍保留
- 回执为 `requestId/modelId/capability/status/healthy/stale/possibleCharge/replayed`，附可选的 `responseTime/code/error`。`succeeded` 是历史效果，只有 `healthy=true` 才表示当前验证仍有效。`stale=true` 表示配置或较新的测试使该证明过时
- POST 的运行中或未知回执是 202；已知失败是 502，过时结果是 409，成功是 200。GET 对存在的任何状态均返回 200；404 只说明本账号查不到该号，不是供应商未计费证明。所有测试及状态响应 `no-store`
- 旧客户端缺少 UUID 会被拒绝，不会兼容成一个没有去重保障的新付费请求

## 持久执行顺序

1. 在账号写锁下读取并校验账本，解析当前配置和凭据指纹，执行请求号与未决输入去重、次数和容量检查
2. 将新测试的 `running` 记录与该能力的 `unknown` 检查原子保存。之前的验证在付费调用之前撤下
3. 每次 HTTP 调用前再次核对目录修订、配置指纹、当前测试所有权与整体截止时间，先持久保存 dispatch 意图，再调用供应商。CAS 或写入不确定时不执行 HTTP，也不自动重试写入后重新发送
4. 单次供应商请求最多等待 20 秒。视觉验证按随机顺序发送红、蓝两张合成图，最多两次调用；在第一张之后的配置变化或检查点失败不会继续第二张。整体截止为准入后的 60 秒
5. 成功回执与能力验证在同一次账号存储写入中提交。目录与模型解析等待该写入成功或回滚后才取得投影快照，不能提前读取内存中尚未提交的 verified。异步读取使用写入代次：跨过提交窗口的旧读不发布到共享数据或 CAS 修订，而是重新读取。较旧测试只可更新自己拥有的验证，不得撤销不同配置或较新测试的成功

能力指纹覆盖实际模型 ID、输出与上下文限制、temperature、输出参数名、语音模式/音色、协议、端点与凭据。此次加入 temperature 后旧版本保存的验证需用户显式重新测试；不会自动发起付费调用。配置与效果准入使用同一份纯数据快照，不能在读取账本后再次刷新数据库修订再写入旧账本。

输入只有固定测试短句和合成色块，不能把请求体的任意文字、真实对话或文件当作测试输入。语音只接受有效 PCM WAV。账本只保存本地模型标识、能力、请求号、配置/输入哈希、修订、计数、时间、状态和固定错误码；不保存明文凭据、端点、模型回复、图像或音频。公共回执也不返回指纹和供应商原始错误。

## 故障与未知结果

- 浏览器断开不会取消已授权的有限测试。它可能继续完成第二张视觉样本，结果保存在原请求号下；客户端只能继续查询
- 网络断开、超时、供应商 5xx/408 没有可靠终态回执时为 `unknown`。第一张视觉样本成功不代表整体成功；第二张结果未知时整次仍是 `unknown`
- 已收到 4xx 拒绝（408 除外）、空文本、错误色块或无效音频是已知测试失败，但 `possibleCharge=true` 仍提醒可能计费。新请求号只允许用户显式决定的新测试，不允许客户端自动补发
- 服务重启或进程死亡留下的 `running` 在截止前仍报告运行中/待确认。超过截止后，有 dispatch 意图的记录保守转为 `unknown`；从未准备 dispatch 的记录转为未发送失败
- 状态核验宣布 `unknown` 后，迟到结果不会自动把它提升为成功。没有供应商回执查询能力，不会根据时间、断连错误或用户刷新推断未计费
- 最终写入失败返回未知；之后的查询可能找到已经成功提交但 ACK 丢失的完整回执，也可能仍是 `running`，最终转为 `unknown`。不会凭缓存中的成功宣称持久成功。LowDB 写入不确定会保留共享数据库实例并使普通读取缓存失效，目录和自动路由也必须重新读取持久状态；读取失败不能回退到旧 verified
- 同配置的 `unknown` 可能长期阻止新测试。本阶段没有撤销未知记录、安全重发、供应商账单核对或费用结算入口。用户应先核对服务商记录；之后若实现人工确认重测，必须作为新的、明确承认额外费用风险的授权流程

## 存储、限额与部署边界

每账号最多 10 次新测试/分钟、100 次/UTC 日、2 条运行中效果、2,000 条效果、10,000 个请求号（包括别名）。重复请求不重新计付费次数。达到容量返回 429；旧号的重放和状态查询仍可用。不会自动淘汰成功、失败或未知记录，避免延迟重试重新计费。容量扩展须采用保留身份和未知效果的审计迁移。

账本与能力证明保存在现有账号存储中。本地 LowDB 依赖单服务进程写锁；不支持多个服务进程同时写同一 JSON 文件。PostgreSQL/MongoDB 依赖现有文档修订 CAS；冲突会阻止发送或提交，不能把 CAS 冲突当作可以再次调用。真实 PostgreSQL 多进程准入竞争有专项测试，MongoDB 此增量只验证读代次单元模型，未运行真实服务验证。

这不是供应商级 exactly-once 或准确账单系统。不得只恢复旧用户 JSON、覆盖账本或把整套存储回滚后继续调用；快照回滚会丢失效果身份。尚无独立于用户数据回滚的效果日志、分布式队列、额度预占/结算与供应商核验机制。生产必须使用持久存储并保留完整效果记录；此变更未部署或调用真实付费供应商。

## 可复验测试

`backend/test/model-probe-recovery.integration.test.js` 用本机 HTTP 模拟供应商覆盖 UUID、账号隔离、并发去重、别名恢复、20 秒真实 HTTP 超时、断网/5xx/408、语音两种协议模式、视觉部分成功、配置变化、浏览器取消、子进程真实终止、迟到结果、写入/CAS 故障、提交 ACK 丢失、容量与损坏账本。

`backend/test/model-probe-recovery-postgres.integration.test.js` 在显式配置隔离 `QUNTHINK_TEST_PG_URL` 后，对实际 PgLow 重复上述用例，并运行独立 Node 进程竞争相同 UUID。数据库缺失时明确跳过；本地单进程通过不能代替真实数据库结果。两个文件都只使用假密钥与合成输入，不进行真实付费请求。
