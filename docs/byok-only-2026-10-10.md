# User-owned AI connections only

## Product behavior

New accounts have no AI providers, models, default model selections, or AI members in the three starter conversation spaces. Users add a provider and model in Model Center, save their own connection, and explicitly test the required capabilities before use. OpenAI-compatible and Anthropic adapters, model discovery, local/keyless connections, custom agents, and capability checks remain available.

There is no platform-funded fallback. `DEEPSEEK_API_KEY`, `GLM_API_KEY`, `MIMO_API_KEY`, `QWEN_API_KEY`, `MIMO_BASE_URL`, `QUNTHINK_SHARED_PROVIDER_KEYS`, and `AI_HEALTH_PROBES` no longer configure or fund AI requests. Leaving old variables in a deployment cannot enable server-funded chat, discovery, TTS, connection tests, or startup health probes. The obsolete process-global load balancer and health-probe implementation have been removed. The legacy `/api/user/apiconfig/test` endpoint returns HTTP 410 without dispatching, even when a user key is saved or supplied; tests must explicitly select a user-owned model through Model Center. Explicitly selected user models remain authoritative; a failed or unavailable selected model does not silently switch to a platform model.

The implicit catalog previously advertised 13 IDs: deepseek, deepseek_reasoner, glm_air, glm_flash, glm_flashx, mimo_flash, mimo_omni, mimo_tts, qwen_flash, qwen_turbo, glm_4v_flash, qwen_vl_plus, and qwen_omni. These IDs are no longer registered automatically. Metadata used to display old conversations or honor explicitly saved user model overrides is retained without endpoints or credentials. Logos and original brand assets are unchanged.

## Existing-account migration

- An explicitly saved per-account `modelCatalog` is preserved, including its model IDs, encrypted credentials, defaults, and verification records. A saved model with an old preset ID is still the user's model; it is not deleted by an ID heuristic.
- Legacy `aiApiConfigs` values stay stored. Meaningful saved connections remain available in Model Center, but saving a provider key alone does not create 13 implicit models. Add the intended model IDs and test them before use. Empty vendor slots do not appear as connections.
- Explicit old `aiModels` model overrides are retained as user-configured models. They do not grant access to server credentials.
- On account load, the JSON, MongoDB, and PostgreSQL adapters use the same idempotent migration for the three known auto-created preset groups. Built-in members with no explicitly saved account model are detached from active membership. Their IDs are retained in `retired_ai_members` for reversibility. Groups, messages, files, reports, custom personas, user-created agents, user-created groups, and scheduled-task records are not deleted.
- Existing user-created agents, groups, and tasks that reference an unavailable old model keep their records and history. They require a user-configured model before further AI calls. Requests fail closed rather than choosing a replacement.
- HTTP persona lists and WebSocket full-persona updates both derive their active models from the user's catalog. A missing catalog never reconstructs preset personas.

No production database or deployment environment has been changed by this source patch. Migration occurs when the updated application loads an account.

## Operations

Deployment templates no longer request platform AI keys. Operators may remove retired variables from their deployment settings after rollout. Any previously exposed key must still be revoked at its provider: deleting runtime support or code does not revoke a credential, remove it from Git history, or protect other services where it is valid. This change does not rewrite Git history.

All added tests use synthetic account credentials or intercepted/loopback transport. No real provider request is needed for verification. Existing integration fixtures now explicitly create user-owned catalogs instead of relying on default models.
