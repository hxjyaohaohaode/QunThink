# 单账号任务前置依赖（F14.3）

## 本次范围

对应《群想项目计划书》的 F14.3 任务前置依赖与阻塞门禁。本功能用于同一账号已有任务之间的前置关系，不新增多人共享权限，也不把任务变成外部办公工具调用或目标（Goal）执行器。旧任务没有前置关系，读取时按空列表处理，旧正文和验收记录保留。

工作台可在创建任务时选择前置任务，也可在已有任务的“前置任务”区域修改。最多直接依赖 32 个任务，账号仍遵守原有 200 个任务限制。自己依赖自己、间接循环和并发形成的环均被拒绝。引用已删除任务与其他账号的任务使用相同错误，不披露其他账号是否存在该任务。

## 何时允许生成或验收

每个前置任务的当前正文必须已经验收，验收版本、正文内容校验和、来源和递归前置关系必须仍有效。运行中、失败、取消、结果未知、缺少验收、前置已删除或来源变化都会阻塞。保留的历史正文可查看，但不会因旧验收仍存在而自动变成有效依据。

派发准入和实际发送到模型前都会重新核验。阻塞时不发送模型请求；派发前依赖变化所取消的本次预算预留会按原日和运行记录释放。前置成果正文不会因选择依赖就自动发送给模型；依赖只建立执行和验收门禁，模型仍使用该任务明确配置的要求及会话上下文。

模型已经收到请求后，修改前置无法撤回已发送的数据或取消既有费用。生成期间前置变化时保留草稿和运行证据，旧稿验收失效，停止自动继续。响应结果未知时保留原有人工核验要求，不自动重发，也不声称未计费。

## 修改、保存和恢复

前置关系有独立的 `dependency_revision`。修改请求必须包含原修订号和 UUID 请求编号；一次新操作成功后修订号增加 1。同编号、同账号、同任务和同内容重放返回原回执，不重复提交；同编号不同内容或过期修订号返回冲突。

设备保存的恢复记录仅包含账号作用域下的任务 ID、依赖 ID、修订号和请求编号，不保存正文或任务标题。响应丢失时先查询原回执，必要时明确重试同一原始请求，不生成新编号覆盖未知结果。任务删除后仍保留回执，迟到重放不复活任务。每条命令按账号、任务和请求编号使用独立设备存储键；多标签同时产生的原编号逐条核验，不互相覆盖或误删。每账号最多保留 10,000 个依赖编辑回执，达到上限后停止新增，不自动遗忘旧回执。

若原选择已无法执行，可选择“核对并结束原前置请求”。服务器先持久保存 cancelled 回执，迟到的原提交会被拒绝；如果原请求已经成功，只返回原成功回执，不撤销关系。收到有效回执之后才释放该编号，才能重新选择。409 冲突或查询 404 本身不能证明同号的另一请求没有成功，不用它们代替耐久封存。

正文保存还携带用户实际核对过的 `reviewed_dependency_signature`。编辑期间后台刷新不会自动升级这个签名；前置变化后需重新核对，明确保存新的复核版本。前置阻塞时允许保存人工文字，但该稿会标记为失效，不能验收；前置后来恢复也不会自动把旧稿升级为已复核。删除全部依赖后同样需要保存新的复核版本。

删除前置任务不会悄悄移除依赖边；后续任务显示缺失并阻塞，用户必须明确修订关系。正在运行或结果未知的任务不允许直接修改其前置关系。

## 自动执行和重启

自动执行遇依赖阻塞时保存至少 60 秒冷却时间，并继续检查后续其他到期任务，不在每个调度周期反复派发同一阻塞任务。依赖恢复后在下一个符合冷却时间的调度周期重新核验；不会因为一次列表刷新直接调用模型。

任务关系、版本签名、编辑回执和冷却时间随原账号数据库持久化。重启不会证明外部请求未执行；已记录发送意图但未取得结果的任务仍按原有未知结果处理，需要人工核验。

## API

- `POST /api/tasks`：可选 `dependency_ids`，旧请求不传即可保持原行为。
- `PUT /api/tasks/{taskId}/dependencies`：`client_request_id`、`expected_revision`、`dependency_ids`。
- `GET /api/tasks/{taskId}/dependencies/commands/{requestId}`：查询该账号该任务的编辑回执。
- `POST /api/tasks/{taskId}/dependencies/commands/{requestId}/close`：空对象请求，核验或耐久封存原命令。
- 任务和正文文档返回 `dependency_state`：`blocked`、原因列表、当前 `signature`、`result_stale`。
- `POST /api/tasks/{taskId}/result/versions`：有依赖或曾编辑依赖的任务须提供 `reviewed_dependency_signature`（有效 SHA-256 或当前阻塞状态的 `null`）；旧的无依赖任务请求仍兼容。

错误包括 `TASK_DEPENDENCY_NOT_FOUND`（404）、`TASK_DEPENDENCY_CYCLE`、`TASK_DEPENDENCY_REVISION_CONFLICT`、`TASK_DEPENDENCY_BLOCKED`、`TASK_DEPENDENCY_CHANGED`、`TASK_DEPENDENCY_REVIEW_REQUIRED`（409）、已封存原请求（410）及持久化结果不确定（503）。完整结构以 `openapi/openapi.yaml` 为准。

## 部署和验证边界

本功能不需要新增服务、模型密钥或数据库迁移。仍须满足原有持久数据目录、数据库、同源 HTTPS 与会话要求。测试使用合成账号、隔离本地数据库和 loopback 模型服务计数，不以真实付费模型验证阻塞。

依赖门禁不等于完整 F14 全部能力，不包含真人多人共享群、跨账号任务、外部办公自动化或 Task→Goal 自动转换。部署、真实国内模型和短信配置的既有外部条件没有被本功能替代。
