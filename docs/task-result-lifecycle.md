# 同会话文稿：版本、依据与恢复契约

## 当前可运行边界

一个已有 Task 就是一份可继续写的文稿，不另建第三种空对象。会话旁与工作台打开同一个编辑器；名称、用途、来源和原生成历史保留。可以没有模型先写正文；只有明确请求 AI 候选才调用已配置并测试通过的服务商。此切片提供文字正文、预览、人工修订、版本确认及文本交付；不代表长期自主执行、真实模型语义质量、所有产品场景或上线条件已经完成。

原 `5056661e681665b7c82c25460af3ea6bc9112f4e` 应用的只读邀请稿缺口保留在历史 Q1 CI 证据中。新用例检验修订后的实际用户结果；不把旧失败改记成功。

## 用户可完成的事情

1. 在会话里保留材料，从某条消息或会话标题打开文稿，说明用途和检查要求
2. 材料范围明确为最近最多 40 条会话消息；单条入口另绑定起始消息。来源 ID/修订记录由服务器维护，不要求把内部 ID 塞进模型提示
3. 直接写正文，或明确请求一个 AI 候选。完整预览不截断文稿
4. 保存不可变人工版本，刷新后打开同一 Task 继续。确认绑定具体版本 ID、正文 SHA-256、文档修订和当前来源 hash
5. 材料修改后显示待复核，旧人工稿及旧确认版本仍可读。用户核对来源并明确保存复核后的新版本，不自动改写日期或覆盖人工句
6. 新 AI 回应遇到已有人工稿时仅成为候选，需明确采用。已有版本保留；采用不等于确认
7. 自动复制被浏览器拒绝时就地说明，并提供全文选择和真实文本下载；不会申请新权限来掩盖失败

学习练习、分支故事及其他产物需要各自的完成条件，本切片不能替代它们。

## 服务器数据与写入边界

Task 内的 `result_editor` 保存加密正文版本、编辑位置和版本确认记录。历史生成稿按其原 run UUID 投影，GET 不偷偷写迁移；人工稿版本使用新的 UUID。客户端不能通过额外字段伪造生成状态或验收。

- 文档 `revision`：保存正文、采用候选、确认版本、更新用途时单调递增
- `head_version_id`：当前编辑基础；旧确认记录可以与它不同
- `accepted_version_id` + `accepted_content_hash`：对特定正文的确认，不暗示新稿已确认或外部任务已完成
- 当前正文的 `source_stale` 与再次生成用途的 `source_input_stale` 独立；已确认文稿按当前版本与确认版本是否相同检索，人工稿无需伪造 run 验收。原来源身份撤回仍隐藏正文，即使它已移出最近 40 条范围
- `source_hash` + source refs：绑定当时可读材料与修订；修改是 `changed`，已撤回/不可读是 `blocked`
- 不完整的旧来源清单只能在 hash 仍一致时展示；发生变化却无法分辨修改/撤回时保守隐藏
- 相关来源删除后隐藏受影响正文，禁止复制、采用、保存或确认；同号旧命令回放也不能重新暴露正文
- 手动文本仍可在生成期间保存；运行未决或结果未知时不能把它标为已确认
- 调整原消息用途需显式绑定当前来源 hash；不启动模型，也不覆盖正文

每份文稿最多写入 100 个新/保留版本，每账号最多 10,000 条正文命令回执，正文限 64,000 字符。达到限制明确拒绝新操作，不淘汰旧稿或未知回执。已有超限历史仍投影保留，归档/配额管理尚未实现。

数据库写锁与读屏障覆盖异步来源核验和写入，防止共享缓存发布未提交版本或替换 CAS 快照。真实 PostgreSQL 的文档 CAS 拒绝跨进程旧修订写入；LowDB 仅支持本轮验证过的单进程账号写锁。未证明 JSON 多进程安全，Mongo 本轮没有实际集成验收。

## API 与最小回执

全部沿用会话认证、CSRF 和预期账号标头；身份以服务端认证为准。响应 `Cache-Control: no-store`。

| 路由 | 行为 |
|---|---|
| GET `/api/tasks/commands/:uuid` | 查询原创建请求；已删除任务仍给最小删除回执 |
| POST `/api/tasks/commands/:uuid/close` | 核对并结束此创建请求；已提交返回原稿，未提交才原子封存该 UUID |
| GET `/api/tasks/:id/result` | 当前文档、历史版本和可见来源变化 |
| POST `/api/tasks/:id/result/versions` | 以 expected revision/base version 保存人工正文 |
| POST `/api/tasks/:id/result/accept` | 确认精确版本、正文 hash 与当前来源 hash |
| POST `/api/tasks/:id/result/adopt` | 明确采用一个仍可读的版本 |
| POST `/api/tasks/:id/result/brief` | 明确更新同一任务的用途及原消息引用 |
| GET `/api/tasks/:id/result/commands/:uuid` | 查询原保存/确认/采用/用途命令 |
| POST `/api/tasks/:id/result/commands/:uuid/close` | 绑定任务及操作核对原命令；已提交返回原版本，未提交才封存迟到写入 |

写入的 `Idempotency-Key` 与 `client_request_id` 必须一致。同号/同输入返回原回执，同号不同输入拒绝；回执包含原版本 ID，不把后来版本当作已确认。命令与正文在同一个用户数据库写入中提交；任务删除保留最小回执，返回 `document:null,task_deleted:true`。404 只说明未找到已提交回执，不证明另一个在途请求不会提交；可继续核验、显式重发完整冻结内容和原 UUID，或明确请求服务端核对并结束该原命令。

丢失写入确认按存储不确定处理，清除未承诺共享缓存，查询原 UUID 恢复。若只有最小回执而未选择保存私密草稿，重载后可查询，但不能把新输入放进旧 UUID 重发。

### 原命令的可靠结束

封存接口是当前账号内对指定 UUID 的一次写入，不是删除文稿、取消已发生的提交或停止 AI。它不接收正文。已有成功回执始终优先，返回原版本或原稿；只在权威存储尚无此命令时写入 `cancelled` 墓碑。墓碑与原写入竞争同一 PostgreSQL 文档 CAS；只允许一个先提交。封存先提交后，同号迟到创建/保存/验收/采用/用途写入永久返回 410，不会复活数据；原写入先提交后，核对返回原成功回执，不能撤销它。已有任务后来删除也保留该回执且不重新显示正文。

`cancelled` 不是正文版本：其 `version_id`、`committed_revision` 和 `committed_at` 均为空，另有 `closed_at`。创建封存的 `task_id` 为空；文稿命令仍绑定原任务和操作种类。GET 和重复 close 均可查询相同终态。409、429、503、连接错误、单独的404或关闭标签页都不是封存完成证据。只清除匹配原 UUID/账号/任务/操作的权威终态记录，保留其他标签页留下的未知请求；当前人工输入不被核验中的旧内容覆盖。

创建准入与模型默认选择使用同一个稳定快照；不得在已判断“没有此回执”后再读取目录，推进 CAS 版本却保留旧判断。普通读取在创建/封存写屏障外等待。创建回执最多10000条，文稿命令回执另最多10000条；达到上限不淘汰旧键，已有回执仍可查询，需后续管理员归档方案。

本地默认不保留私人草稿时，刷新已经丢失的原文无法由最小回执还原。封存成功后需重新填写或从已保存版本继续；不能承诺原文恢复。此协议不涵盖供应商撤单/退款、后台隐私删除、浏览器存储被人为全部清除或当前尚未覆盖的跨产品操作。

## 四类保存互不替代

- **服务器正文**：已保存版本和来源，服务器是权威；加密存储不等于无密钥风险，仍需生产密钥管理与备份验证
- **设备离线副本**：用户明确开启，保存在该账号的设备加密区域；离线时不证明当前来源/权限，不可提交或确认
- **未提交草稿**：设备恢复默认关闭，开启后保存加密正文及冻结请求。关闭时当前页面缓冲保留，但未提交内容重载可能丢失；关闭/刷新有提示
- **最小命令回执**：账号分区的 UUID、操作种类、必要对象/版本 ID、hash 与时间，不含正文、标题、提示词、服务商密钥。它独立于内容缓存选择；未决回执可在同账号重新认证后核验

退出或清除私人内容会失效账号/逐稿跨标签写入代次，防止已开始的加密写在清理后复活。迟到请求按账号认证代次隔离；较新的撤回观察不能被旧成功回执恢复正文。浏览器自身存储被清除时，本地恢复标识也可能丢失，不能承诺设备外的恢复能力。

## 本地与真实界面证据

新后端专项覆盖同稿完整变化链、严格输入、跨账号读取、冲突、丢确认、任务删除回执、来源撤回、旧记录保守处理、生成晚回保留人工稿、未承诺写屏障及真实 PG 多进程 CAS。前端定向检查恢复顺序、撤回屏障、跨账号与跨标签内容清理、输入法与下载/选择退路。它们不等于界面体验通过。

CI 的 `product-results.spec.ts` 通过实际控件检查完整 Q1、零模型人工起写及原命令重载恢复、已发出模型调用的停止/未知状态。保留自然帧、视频、trace、实际正文与下载文件、状态回执。所有模型输入输出是隔离的确定性 HTTP 夹具；不证明真实模型理解或供应商费用。最终结果以精确提交对应 CI 和独立图像审查为准，不用本地 `--list`、DOM 或测试数量代替。
