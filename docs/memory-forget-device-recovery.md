# 遗忘请求：无正文的设备核验与回显屏障

本包基于 `d91438adc52191c77153eee970bc6c6d24b9caa8`。它补充[既有记忆交互说明](memory-recovery-2026-10.md)，不改写此前仅当前标签页恢复的历史验证结论。当前文件描述候选契约；原生浏览器与独立产品验收结果须另按最终提交和工件记录。

## 用户能完成的任务

用户确认遗忘后，即使请求未送达或成功回执丢失，刷新、关闭页面后重新登录同一账号，仍能找到这条记录的核验入口。正文在结果未知期间保持隐藏。入口先展示请求时间、短记录编号及完整编号展开项，并说明按钮将再次请求遗忘同一记录并核对结果。

这不是独立操作 UUID 的查询接口。现有服务是 `POST /memory/:memoryId/forget {}`：对同账号的固定记录执行幂等遗忘，确认返回同一 `memoryId` 与 `forgotten: true`。只有实际客户端验证该成功回执，才能将此次核验标为完成。404、空列表、来源不可用或连接失败不能替代成功回执；仍可稍后核验，不会自动另建记录。

## 四类数据不混同

- 服务器记忆：仍由既有账号数据库和独立删除账本管理。
- 未提交笔记、更正正文：仍只在当前标签页内存；本包未增加私人正文离线缓存，也未实现创建或更正请求的跨刷新恢复。
- 待核验遗忘：本设备只保存版本、账号归属、固定记录编号、开始时间和待核验状态。不保存正文、类别、来源、草稿、供应商密钥或错误堆栈。
- 已确认回显屏障：成功后保留同一份无正文元数据及确认时间，阻止其他窗口的旧列表、保存回执或更正对照重新显示已遗忘内容。它不占待核验请求准入配额。

账号切换或退出会清空当前页面投影，不向新账号显示其他人的核验项。重新登录同一账号可恢复该账号的入口；恢复不会自动发出遗忘 POST。设备记录按账号和固定记录编号分键，避免一个列表的整体覆盖丢掉另一条请求。

清除浏览器站点数据会删除设备核验信息，不能承诺之后还找得到未完成请求；它不会撤销服务器已经完成的遗忘。本包也不保证已导出文件、外部副本、其他设备或整卷备份已经物理删除。

## 并发与异常边界

1. 先记录并读回设备核验元数据，再发出遗忘请求。存储拒绝或配额不足时不派发，并明确说明尚未发送。
2. 成功回执后的完成屏障若未可靠写入，保留同一记录的核验入口，并区分“服务器已确认”与“设备尚未记录完成”。
3. 待核验新请求的准入限制为 512 条。并发导致已存在条目暂时超过限制时，仍可读取并逐条核验，不把合法超限队列当作损坏。不会为腾位置淘汰未决请求或已确认屏障。
4. Web Storage 枚举不是跨窗口快照。除了枚举发现入口，每次发布列表、创建/更正成功正文、当前版本对照及开始编辑时，都直接读取该具体记录的屏障键。读取错误保守隐藏旧投影。
5. 跨窗口事件使用原事件中的已验证旧/新元数据，避免另一个窗口已经完成操作后，当前存储快照遗漏整个变化。事件只用于撤下正文或呈现核验入口，不被当作新的服务器操作回执。
6. 旧账号或旧会话的异步完成不能清除重新登录后的待核验项。原更正/保存回执即使曾成功，若已有遗忘屏障，也不能再显示旧正文或用“笔记已保存”掩盖后来的隐私状态。
7. 设备屏障会随已遗忘记录增加而占用浏览器存储。最终存储限制仍是实际边界；错误必须明示，不得清掉屏障后谎称请求已经派发或已完成。

## 服务与验证范围

当前后端记忆依赖 `CustomLow` 的独立删除账本，未接入该机制的 PostgreSQL/MongoDB 记忆接口仍明确返回不可用。本包不改变后端，不将任务模块的 PostgreSQL 并发通过结论挪用于记忆。

本地自动化使用真实 MemoryCenter、store、memory API 与 Axios，配合合成传输和可控存储交错；这不等于原生浏览器多窗口实测。技术测试包含丢 ACK、刷新重建状态、账号往返、迟到列表/更正/创建、事件排队、枚举位置变化、多个 ID、并发超额准入、存储不可读和完成屏障写失败。

独立原生验收须先在冻结旧应用记录两个实际断点，再在候选上执行恢复与终态核验，保留自然视口、trace、视频和具体请求证据。原生多键/多窗口、全站缓存选择或全部无障碍检查若未实际操作，仍须单列未覆盖。
