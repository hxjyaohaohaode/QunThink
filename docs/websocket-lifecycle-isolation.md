# WebSocket 会话生命周期与恢复边界

本次只覆盖浏览器 WebSocket 服务及其发起的数据恢复，不代表全部聊天、缓存或多人部署已经验收。品牌、logo、登录页面和入口动画保持原样。

## 所有权与退出

- 一次主动连接绑定账号 ID 和认证代次；每个 socket 另有独立上下文。即使 A → B → A 回到同一账号，旧事件仍失效。
- open、message、error、close、批量子事件，以及连接超时、心跳、错误消退、重连定时器都验证当前所有权。旧 4001 不能使新登录过期，旧 close 不能关闭新连接的心跳。
- disconnect/destroy 先撤销所有权，再清理定时器、监听器、选择的群组、内存游标并关闭 socket。网络恢复或页面重新可见不会复活已退出的连接。
- 服务自己发起的 HTTP 请求在 Axios 异步拦截器之前固定认证代次及期望账号，附带每连接 AbortController；关闭/替换时取消请求。每次 await 后仍检查所有权，以防不可取消的迟到结果。
- 有效连接的 4001 显示固定认证提示并发出过期事件，不回显服务端关闭原因。普通 1000/1001 不自动定时重试。

## 有界恢复

- 连接超时 20 秒；心跳每 30 秒检查一次，45 秒未收到有效帧即关闭并退避。
- 异常关闭最多自动重试 30 次，带指数退避和抖动，单次最大 30 秒。上限后明确提示刷新，不再用 60 秒兜底无限重试；online/visibility 不能跳过退避或上限。
- 仅在连接打开至少 30 秒后仍收到有效帧，才认为它稳定并重置重试预算。只打开但始终沉默的端点不能不断重置预算。
- 每连接、每群组只允许一个补读。已有显示历史时按原游标最多补 5 页；冷标签页不能把持久化游标当作已加载历史，而是恢复该账号 IndexedDB 缓存后读取首屏。
- 缓存恢复和 HTTP 完成均有所有权检查；未确认的失败草稿保留。确认回执按 client_message_id 对齐，迟到缓存不能在已收到实时确认后重新加入同一失败草稿。
- 首屏成功回执只核对实际返回页时间范围内的已确认缓存，保留未发出草稿及读请求期间新增/改变的消息。hasMore为真时，更早历史不能被误当删除；之后加载较早页继续核对。范围之外的缓存还未经最新服务端确认。
- 在补读期间到达的删除保留删除标记；对尚未加载消息的编辑、反应与评论，在该消息恢复后应用一次。已显示的实时消息不被旧 HTTP 正文回退。
- 群组/角色刷新按字段合并请求期间的变动：实时预览或一个角色的编辑不会使新加入的其他群组/角色整批丢弃。新群组会订阅并补读。

## 日志与验证范围

WebSocket 服务不记录消息/错误正文、关闭原因、URL 或角色名字。解析失败只记录固定类别；用户可见错误使用固定文案。上游 API 拦截器和存储模块的日志、账号隔离需单独审查，不能由本文件的检查推导安全保证。

`frontend/test/websocketLifecycle.test.mjs` 执行实际 WebSocket 模块和实际 Axios/认证拦截器，使用可控 WebSocket、时钟、存储效果和 HTTP adapter。覆盖过期事件、A-B-A、同账号替换、迟到 401、取消、缓存读取、补读分页、实时交错、草稿对齐、终止恢复和有限重试。它不是实际浏览器或实际 IndexedDB 引擎测试，也不证明服务端认证、共享 cookie 的所有外部变化、多进程部署或第三方副本删除已验证。

本地浏览器 loopback 被策略拦截，未尝试绕过。本包真实浏览器结果必须读取后续集成提交的 CI；以前提交的绿色 CI 不能替代本包。
