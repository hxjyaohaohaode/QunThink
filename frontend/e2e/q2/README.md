# Q2 原请求恢复：实际界面证据

本目录通过真实 Chromium 控件操作，检查创建、正文保存与已删除文稿的最小回执恢复。它是 Q2 数据自主场景中的有界切片，不代表全部记忆删除、离线策略、多账号或跨产品状态已经验收。

## 执行与隔离

仅授权 GitHub Actions 中执行 `npx playwright test --config=playwright.q2.config.ts --project=<project>`；本地 `--list` 只发现用例，不启动监听器或浏览器。复用现有严格 CI 门禁、隔离开发账号和明确 loopback 服务。每个项目单独运行，模型目录未配置可用模型，最终要求夹具调用数为零。生产短信、真实供应商、生产数据库和人工连续操作体验不在此证据内。

CI 将 `core`（原浏览器套件及 Q1）与 `q2` 分开运行、存档。所有成功/失败均保留自然视口、完整截图、视频、trace、JSON ledger 和实际文本下载。没有强制禁动画、修改样式、设置路由或注入前端 store。品牌与源码在起止检查中保持一致；完整性检查失败单列，不覆盖先发生的界面错误。

## 三条任务与明确边界

1. **创建请求**：零模型主入口起写 → 原 POST 未准入并断连 → 刷新后确实丢失未选保存的私人文字 → 原 UUID 查询404 → 重新填写 → 结束请求暂不可达仍保留当前输入 → 封存成功但 ACK 丢失且浏览器回执读取暂不可达 → 刷新后同 UUID 核验 → 明确终态后才发新 UUID。另测原创建其实已提交时，返回原稿而不覆盖后写的文字，新输入真正保存为独立意图。
2. **同稿正文**：建立并确认一个真实人工版本 → 对新的正文保存操作重复上述未准入/关闭 ACK 丢失/恢复链 → 返回已提交原成功时继续保留新的输入 → 再次保存与下载实际新正文。原稿 ID、已确认旧版本和原文字保持不变，新版本不伪称已确认。
3. **已删除文稿**：从可见控件明确删除独立合成文稿 → 刷新、任务列表为空 → 仍能从最小操作入口核验原保存 UUID → 结束未提交操作后显示原地确认。迟到写入不能恢复已删正文或创建新任务。

“D 不可达”分支明确注入的是关闭请求不可达，不代表所有查询都失败。C 是关闭已提交但 ACK 丢失与后续浏览器回执读取暂不可达的组合故障。每次实际界面只维护一条待确认键；多键、多标签和 A/B/A 的技术检查不能借此提升为完整原生界面通过。

## 迟到请求不是新造的 API 操作

测试仅暂存从实际控件发出的原 `Route`/`Request`。封存前确认其没有转发；封存后使用该对象的 `route.fetch()` 原样送达，关闭自动网络重试与重定向。比较 method、URL、原正文 SHA-256、幂等键和预期账号。必须收到具体 `TASK_CREATE_COMMAND_CLOSED` 或 `RESULT_COMMAND_CLOSED` 的410；403/404不算封存证明。之后再次读取权威任务/版本，确认没有复活、重复写入或删除旧成果。如果刷新后的原 Route 无法被工具送达，该段记为取证受阻，不重新拼装近似请求冒充原始延迟。

会话若实际出现同源认证429，只按捕获的 `Retry-After` 等待，保留原画面与起止时间后点击真实“重试连接”。没有429证据就不会盲目等待或绕过登录。等待结束不代表体验速度合格；当前应用限流页仍需更明确的等待提示。

## 工件核验

Q2 工件名含 `qunthink-browser-evidence-q2-<project>`，以及 `qunthink-browser-evidence-q2-parts-<project>-manifest/part-NNN`。每片20MiB，最多16片；超限明确失败，不丢弃视频或压缩质量。用仓库 `scripts/pack-ci-evidence.mjs restore` 校验并还原完整 tar，核对官方 artifact ID、size、digest、run/head 和 PR 虚拟合并树。列表连接器只有一页时，按完整工件名查询，不能将第一页误当全部。

最终可用性结论以精确提交的实际运行结果、原图/视频/trace和独立产品审查为准；DOM、服务测试、`--list` 和测试数量均不替代这些证据。
